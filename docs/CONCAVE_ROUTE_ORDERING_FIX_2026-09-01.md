# 凹多边形短航带连接优化（2026-09-01）

## 原因

凹多边形的一条扫描线可能被边界切成多个航带片段。原实现生成的基础蛇形顺序正确，但为了支持四个起始角，候选路径会直接交换每条航带方向或反转整个扁平列表；这会破坏同一扫描行内多个片段的顺序。`AUTO_NEAREST` 又只比较候选首点到参考点的距离，没有比较后续空飞距离。

表现为短航带完成后连接到区域远端，再返回另一条短航带。覆盖、照片数量和飞行速度都没有问题，浪费发生在不拍照的连接段。

## 修复

- 每个片段保留 `scanLineIndex`，四个起始角按扫描行整体翻转，行内同步反向。
- 发现一行多段时，固定所选起始角后，优先连接最近的剩余片段和端点。
- 对不超过 512 条航带的复杂任务做有界 2-opt 去交叉优化；128 条以内最多 128 次改进，大任务限制轮数，避免规划时间失控。
- `AUTO_NEAREST` 改为比较“飞向候选起点 + 候选内部连接”的总代价；显式选择四角和 CUSTOM 仍保持用户指定语义。
- 仅重排航带和方向；ROI、覆盖间距、航点高度、拍照视角及数量不变。

## 验证

- 合成 U 形凹多边形覆盖四个起始角，禁止产生远端跳线。
- AUTO 起点与四个候选的“进入 + 内部连接”最小总代价一致。
- 当前手机任务专用只读回归：ROI、691 张照片、五组视角序列不变；连接总量必须下降 40% 以上，最大连接下降 50% 以上。
- 73 项本轮相关 JVM 测试通过；手机任务专用回归另行通过，常规 CI 中无手机 fixture 时标记跳过。

旧任务 JSON 不会自动重排。安装修复版后需要重新点击“生成所选 5 组”，核对预览并重新预检/上传；不能直接执行手机里现存的旧航线来验证此修复。
