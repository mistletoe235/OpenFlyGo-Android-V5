# V5 公私版本 Git 对齐与内存回归核查

## 结论与边界

这次不是把“私有版本整体裁掉模型功能”后重新发布，而是在 9 月 4 日公共快照上逐次同步。
此前对齐主要覆盖航线代码，没有覆盖 UXSDK 地图的历史修复，确实漏了已经修过的问题。
能编译和航线单元测试通过，不等于整个 App 与私有版等价，更不等于真机长时运行已通过。

- 公开 V5：`6c43117`，2026-09-27，已发布 `0.1.10-v5`。
- 私有 V5：`dcd6c68`，2026-09-22，另有大量未提交修改。本次同时比较 HEAD 和工作区，没有只看提交日期。
- 两个 HEAD 共有 847 个生产 Java/Kotlin 文件，813 个相同、34 个不同；此数字不含测试、资源或私有独有文件。

- 5 个共用相机文件中，4 个逐字一致；`CameraCaptureController` 的新录像/模式确认改动需要单独评审，见下文。

## 9 月 27 日真机故障证据

12S 上 `com.openfly.go.v5`、版本 `0.1.10-v5`、进程 8685：

- 12:40:33–35，Java 堆达到 254/256 MiB，GC 后仍无法释放足够空间。
- 12:40:34，分配约 1.6 MB 对象失败；随后连 32 字节分配也报 `OutOfMemoryError`。
- 12:40:35，致命异常栈包含百度地图 `NABaseMap.nativeAddOneOverlayItem`；主线程处于 `WaitingForGcToComplete`。
- 12:43:04，系统记录输入事件等待超过 5001 ms 的 ANR。

这些证据证明本次发生堆耗尽和地图调用处的致命异常，不能仅归因于自动锁屏。
本次没有获得可用的堆转储，不能凭分配失败位置声称全部存活对象都属于地图。
历史 9 月 11 日堆转储曾直接证实百度地图执行器积压 46,497 个任务；对应修复恰好在公开版缺失。

原始日志保留在本机私有临时证据中，不把飞行坐标、用户任务或完整日志加入公开仓库。

## 本次补齐

1. **地图显示**：恢复每 200 ms 取最新状态；移除每次遥测新建动画；相同位置/朝向不重复提交；
   轨迹每秒更新且最多 1024 点。保留公开版旧 Android 定位回调兼容写法。
2. **执行航线覆盖物**：公私版原先都反复删除、创建航线和目标标记。本次两边均改为复用、按差异更新；
   UI 最多保留一个待刷新任务，任务清空/页面关闭会取消待刷新工作。仅样式改变时重建必要的连接线。
3. **VS 控制权释放**：同步私有工作区的 `VirtualStickDisableCompletion`。
   同时等待本次 disable 指令回调和已禁用状态；用代次隔离迟到回调，防止上一轮释放误伤新控制租约。
   没有同步高频雷达/XYZ 私有日志，也没有改控制发送频率。
4. **离地高度单位**：公开监听和缓存读取原来除以 100，改为共用的分米转米函数。
   DJI 官方 `KeyUltrasonicHeight` 定义单位为 dm；已同时核对监听与读取路径。未引入底层 OSD/雷达依赖。
5. **HIL 位姿过期**：同步 `predictFresh`，原生仿真位姿过期后不再用另一来源的缓存数据冒充本轮新样本。
6. **HIL 折叠页面预览**：同步弹窗预览与关闭时释放图片；避免图像被写到隐藏的内嵌预览控件。
7. 保留前一轮屏幕常亮修复；本次 V5 构建版本为 `0.1.12-v5` / code 14。

官方单位说明：
[FlightControllerKey / KeyUltrasonicHeight](https://developer.dji.com/api-reference-v5/android-api/Components/IKeyManager/Key_FlightController_FlightControllerKey.html#key_flightcontroller_ultrasonicheight_inline)。

## 不应反向覆盖的差异

| 类别 | 保留原因 |
| --- | --- |
| MNN/VLN、AirBrain、室内规划、RC2 桥接、底层 OSD 和雷达录制 | 不属于公开航线产品范围，不整目录复制 |
| `SurveyFeatureAvailability` / `SurveySimulatorExecution` / WPMZ 入口 | 公开安装包禁止仿地；不能因私有代码差异恢复入口 |
| `V86Contract`、云端任务入口 | 公开版已有 schema 13/14 声明、预览/导入区分和补拍参数；不能覆盖成私有旧实现 |
| `V86HttpClient` | 公开版使用可配置端点，不复制私有服务地址 |
| `SurveyFeatureController` 手机存图 | 公开版默认 false，基于偏好读取；不能恢复默认保存图片 |
| `GpsPositionClosedLoop` / 速度上限 / 手动 XYZ | 私有工作区增加模型连续运动与更高速度；不是航线公共控制器的等价替换 |
| 私有测试中的绝对 fixture 路径 | 不复制个人路径、任务或素材到公开源码 |

`CameraCaptureController`：私有工作区尚未提交的修改主要是录像等待模式/存储就绪、
不再把“模式命令已接受”直接写成已切换、以及日志。这次没有整文件复制：
它带有新的存储状态等待条件，不能未经机型验证就再给公开版增加门槛。
航线确实也使用这个控制器；共同的拍照等待/发送实现已单独比较，不能因此声称整文件一致。
此项保留为明确的差异评审项，不把所有私有未提交功能当成已经验收的发布修复。

## 防止再次漏同步

```sh
python3 scripts/check_private_v5_parity.py --private-root /path/to/private-v5
```

该命令比较工作区原文，不计算哈希、不复制文件、不改飞机状态：

- 共用航线、相机、账号、地图和 mapkit 目录按文件对比，缺文件也失败。
- 单独检查控制权、HIL 位姿、航线图层复用等核心文件/代码段。
- 目前 180 项共用检查通过；3 个明确差异项打印 `MANUAL REVIEW`，不是静默当作已对齐。
- 该检查只防止列出的共用实现漏同步；不替代对剩余 UI、构建配置、模式切换和硬件行为的人工评审。

  最终状态不丢失，固定场景只创建 3 条线和 2 个标记，静态图层不重复更新。
- 暂停、转场样式、目标切换、几何缺失、清空、重新开始均有覆盖。
- 新增源代码接线测试，检查实际 MapWidget/控制端口/遥测入口确实使用修复，防止仅辅助类通过测试。

- 私有定向：App 19 项、UXSDK 6 项全部通过。
- 对齐检查负例：模拟公开版缺失 `MapDisplayPolicy`，命令正确失败；未改动实际仓库文件。
- 签名 Release 构建、R8、`lintVital`、签名和 APK 对齐检查通过；保留既有 DJI SDK 资源与 R8 警告，不把它们写成零警告构建。

上述“30 分钟”是虚拟时钟和假地图接口的逻辑回归，不是真机百度地图连续飞行 30 分钟。
