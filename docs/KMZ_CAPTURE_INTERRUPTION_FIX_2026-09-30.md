# KMZ 拍照进度与中断状态修复（2026-09-30）

目标版本：`0.1.13-v5` / versionCode `15`。

## 影响范围与根因

公开 V5 `0.1.12-v5` 的 KMZ 执行、手机拍照路径仍包含以下缺口：

- 普通航带到达末端，但最后一张因相机忙、拍照间隔或姿态不符而未发出时，
  拍照协调器可能仍停在旧航带。飞机转向后继续拿旧航向判断拍照条件，形成持续漏拍。
- SDK 监听跟随适配器生命周期，而非每次执行或续飞会话；旧会话通知缺少代次隔离。
  现场观察到执行索引停止更新，但现有证据不能证明 SDK 内部停止通知的原因。
- 飞控已返航时只保存断点，仍等待原生航线状态通知结束本地执行。
  此后原生暂停可能被拒绝，界面和手机拍照调度却继续认为任务在执行。

这些属于 V5 KMZ 路径。V4 和 iOS 的自有虚拟摇杆执行器不使用这套 SDK 航线监听；
本次不修改它们，也不因此宣称其所有飞行场景均已验收。

## 修复方式

1. 到达普通航带末端且没有待完成的末端拍照请求时，推进航带，不再等待拍照器 inactive。
   未发出的末端照片不计为成功；航带中间的等待、点拍确认和原有姿态阈值不变。
2. 每次执行、断点启动、恢复重新建立监听；忽略旧代次回调，并记录订阅代次与执行信息计数。
3. 用新鲜飞控返航/降落状态结束本地执行，停止手机拍照并保存恢复信息。
   本地状态对齐不发送取消返航、起飞或其他飞行命令。
4. 暂停被拒时仍记录错误；只有新鲜遥测明确飞机已脱离航线、处于普通手动飞行时才对齐中断。
   航线模式、准备阶段、未知模式、断连或陈旧数据不能伪装为暂停成功。

中断判断的遥测时效不是拍照新增门槛；不恢复普通航带逐字段 1 秒更新要求。
公开版保留地图、常亮、云端航线与点云功能，手机存图仍默认关闭，仿地仍禁用；
不引入私有模型、推理模块、遥测记录、服务地址或飞行日志。

## 验证与现场验收

新增反向航带测试在旧代码上失败：期望进入航带 1，实际仍为航带 0。
回归覆盖末端姿态不可用、执行索引陈旧、续飞监听重建、旧回调、返航无原生状态回调、
暂停拒绝后的状态对齐，以及未知/陈旧遥测不能判为成功。

公开代码验证结果：定向 49 项全部通过；完整 `:app:testReleaseUnitTest` 共 633 项，
631 项通过、2 项跳过、0 失败。原有跳过不计入通过数量。

`:app:assembleRelease` 通过，正式 APK 为非调试包，签名校验和 16 KB ZIP 对齐检查通过。
签名证书、DJI 和地图授权配置均与上一版正式包一致；这些私有配置未写入公开源码。

单元测试与 APK 构建不能替代实飞。后续由操作者验证换电续飞、反向航带拍照、
遥控器返航后界面收尾及取消返航后的恢复入口。
发布状态与下载以 GitHub Release `v0.1.13-v5` 为准；发布不代表已完成飞行验收。
